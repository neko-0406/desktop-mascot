# 要件定義書 (Requirements Specification)

## 1. プロジェクト概要

### 1.1 プロジェクト名
**Desktop Mascot (デスクトップマスコット)**

### 1.2 目的・ビジョン
VRChat向けアバター（Unityアバタープロジェクト／VRCSDK3形式、lilToonシェーダー、VRC PhysBone設定済み）を、高効率かつ手軽にWindowsデスクトップ上に常駐させ、ユーザーとインタラクションを行うデスクトップマスコットアプリケーションを開発する。

従来、VRChat向けアバターをデスクトップ上に表示・動作させる場合、VRMへの手動変換（シェーダーやPhysBoneの再設定）や高負荷なゲームエンジンの常駐ランタイムが必要とされていた。本プロジェクトでは、Unityプロジェクトから独自バイナリ形式（`.dma`）への半自動エクスポートパイプラインと、Rust + wgpuによる軽量・省電力・高忠実度な専用ネイティブランタイムを提供することで、日常的なデスクトップ作業の邪魔をせず、ユーザーのお気に入りのアバターが生き生きと動く環境を実現する。

---

## 2. システム構成・対象環境

### 2.1 動作対象環境
- **OS**: Windows 10 (64-bit) バージョン 20H2 以降 / Windows 11 (64-bit)
- **グラフィックスAPI**: DirectX 12 または Vulkan (wgpu経由)
- **推奨ハードウェア**:
  - CPU: Intel Core i3 8th Gen / AMD Ryzen 3 2000番台 以上
  - GPU: DirectX 12 Feature Level 11_1 対応の統合GPU（Intel Iris Xe / AMD Radeon Vega）または専用GPU（NVIDIA GTX 1050以上）
  - RAM: 8GB 以上 (本アプリ単体の消費メモリは 200MB 以下を目標)

### 2.2 開発スタック
- **言語**: Rust (ランタイム本体・ツールチェーン) / C# (Unityエディタ拡張エクスポートスクリプト)
- **ウィンドウ管理**: `winit` + Win32 API (`windows-rs` / `windows-sys`)
- **レンダリング**: `wgpu` (WGSL シェーダー)
- **GUI (吹き出し・設定画面)**: `egui` (`egui-wgpu`, `egui-winit`)
- **エクスポート環境**: Unity 2022.3 LTS (VRCSDK3-AVATAR 導入済みプロジェクト)

## 3. 機能要件 (Functional Requirements)

### 3.1 アバターインポート＆変換 (Pipeline)
1. **Unityプロジェクトからのワンクリック／CLIエクスポート**:
   - Unityのバッチモード (`-batchmode -nographics`) を用いて、Unityプロジェクト内のシーンまたはプレハブからアバター情報を抽出。
   - `VRC_AvatarDescriptor` を自動検出し、対応するボーン構造、メッシュ、ブレンドシェイプ、マテリアル、PhysBone、アニメーションクリップを抽出。
   - 複数アバターが存在する場合の指定抽出（CLI引数または選択UI）。
2. **独自最適化フォーマット (`.dma`: Desktop Mascot Avatar)**:
   - 高速な起動（ゼロコピー／mmap対応）が可能な単一バイナリ形式。
   - 頂点データ、マテリアルパラメータ（lilToonプロパティ）、スケルトン階層、PhysBoneパラメータ、表情ブレンドシェイプ定義を統合格納。

### 3.2 ウィンドウ表示と透過合成
1. **完全透過・枠なしウィンドウ**:
   - 背景が完全に透明化され、キャラクターのみがデスクトップ壁紙や他アプリの上に浮遊・設置される。
   - Windows DWM (Desktop Window Manager) と連携した高品質なアルファブレンディング。
2. **最前面表示 & クリックスルー (透過ヒットテスト)**:
   - 常に最前面表示 (`WS_EX_TOPMOST`)。
   - キャラクターが存在しない透明ピクセル領域をクリックした場合、背面のアプリケーション（ブラウザやエディタ）へ入力イベントを透過 (`WS_EX_TRANSPARENT` 動的制御、またはクリック判定による透過処理)。
   - キャラクターをクリック／ドラッグした場合は、マスコットへの入力として捕捉。
3. **ウィンドウとアバターの位置追従**:
   - キャラクターのバウンディングボックス（AABB）に基づき、必要最小限のウィンドウサイズを維持。
   - キャラクターをドラッグした際、ウィンドウ座標そのものを移動させることで、マルチモニター環境や画面端でも自然に移動可能。

### 3.3 レンダリング＆シェーダー (lilToon再現)
1. **Toonシェーディング (2段階陰影)**:
   - ベースカラー、影色（陰影パラメータ・フェザー調整）によるアニメ風レンダリング。
2. **Inverted Hull (裏面押し出し) 方式のアウトライン**:
   - 頂点法線方向にメッシュを拡張し、裏面描画することで自然な輪郭線を生成。
3. **段階的なlilToon機能サポート**:
   - アルファテスト (Cutout) および アルファブレンド (Translucent)。
   - MatCap (髪の毛や金属などのハイライト・光沢球マッピング)。
   - Normal Map (法線マップによるディテール再現)。
   - RimLight (輪郭発光・フレネル反射)。
   - Emission (自己発光テクスチャ)。

### 3.4 物理演算＆アニメーション
1. **VRC PhysBone 物理シミュレーション**:
   - 揺れもの（髪の毛、スカート、アクセサリ、胸部、耳、尻尾など）のリアルタイム物理演算。
   - Verlet積分によるばね・ダンピング・復元力（Stiffness）の再現。
   - 球体 (Sphere) および カプセル (Capsule) コライダーとの衝突判定。
   - VRM SpringBone のインポート／フォールバック互換性。
2. **基本モーション & アイドリング**:
   - Humanoid互換のボーン階層による待機（Idle）アニメーションループ。
   - 呼吸モーション、定期的な立ち位置の組み替え。
3. **表情・視線制御**:
   - まばたき（ランダムな自然周期による自動瞬き）。
   - マウスカーソル追従（Look-At）: 首・頭のボーンおよび視線用ボーン／ブレンドシェイプがカーソル位置を滑らかに追従。
   - 表情プリセット（喜怒哀楽、驚き等）の切り替え。

### 3.5 インタラクション & AI対話
1. **ダイレクトインタラクション**:
   - クリック（タップ時のリアクション・ボイス/吹き出し）。
   - なでなで（頭部付近でマウスを左右に往復させた際の撫でられ反応、表情変化、PhysBoneの微振動）。
   - つまみ上げ・ドラッグ（持ち上げられた際のぶら下がりポーズ、揺れものの重力追従）。
2. **吹き出し (Speech Bubble) 表示**:
   - アバターの頭上に追従する半透明吹き出し。
   - テキストのタイピング風ストリーミング表示。
3. **分離型AIアーキテクチャ**:
   - **Action Selector (行動決定モジュール)**:
     - Level 1: 決定論的ステートマシン / ルールベース（時間経過、ユーザーの放置度、マウス操作に応じた行動分岐）。
     - Level 2: LLM駆動の自律行動選択（気分・コンテキストに基づく行動決定）。
   - **Comment Generator (発話生成モジュール)**:
     - Level 1: 定型文テンプレートプール（ランダム選定、感情パラメータ連動）。
     - Level 2: クラウドLLM連携（Google Gemini API, Anthropic Claude API, OpenAI API等への非同期リクエスト）。
     - 将来的なローカルLLM/TTS（VOICEVOX等）への拡張スロット。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 パフォーマンス & 省電力性
- **フレームレート**:
  - 通常動作時: 60 FPS (V-Sync同期) を安定維持。
  - アイドル・バックグラウンド省電力モード: ユーザー操作がなく、かつアニメーションが停止している場合、15〜30 FPS へ動的ドロップ、または再描画頻度を抑制（Demand-Driven Rendering）。
- **CPU / GPU 使用率**:
  - アイドル時のCPU使用率: 1〜2% 未満 (Core i5 基準)。
  - アイドル時のGPU使用率: 2〜5% 未満。
  - ゲーミングや重い作業の邪魔にならない低負荷設計。
- **メモリ使用量**:
  - プロセス起動時: 80〜150MB 程度。
  - 4Kテクスチャ等を含む高解像度アバター読み込み時でも 300MB 以内を目標。

### 4.2 安定性 & 堅牢性
- **クラッシュフリー**: Rustの所有権モデルとメモリ安全性により、バッファオーバーフローやヌルポインタ参照によるクラッシュを徹底排除。
- **エラーハンドリング**: Unityプロジェクトのエクスポート時、不足しているコンポーネント（VRCSDK未導入、シェーダーエラーなど）が存在してもユーザーフレンドリーなエラーメッセージを出力。
- **マルチディスプレイ / 解像度変更対応**:
  - ディスプレイのスケーリング（100%, 125%, 150%, 200% 等のHiDPI）が混在するマルチモニター環境において、DPI変更イベントに追従して歪みなく再スケーリング。

## 5. ユースケース & ユーザーストーリー

### ユーザーストーリー 1: VRChatユーザーが自分のアバターを手軽に呼び出す
> **As a** VRChatのヘビーユーザー  
> **I want to** Unityで普段使っている自分の改変アバターを、面倒なVRM変換作業なしでデスクトップ上に呼び出したい  
> **So that** 日常のPC作業中も大好きなアバターと一緒に過ごすことができ、PhysBoneの揺れやlilToonの質感をそのまま楽しみたい。

### ユーザーストーリー 2: PC作業の邪魔にならない省電力常駐
> **As a** PCで重い作業（プログラミング、動画編集、ゲーム）を行うクリエイター  
> **I want to** マスコットが画面端にいてもCPUやGPUの負荷にならず、クリックが背面のウィンドウを邪魔しないようにしたい  
> **So that** 作業効率を落とすことなく、癒やしとして常駐させておける。

### ユーザーストーリー 3: インタラクションとAI雑談による癒やし
> **As a** デスクトップマスコットのユーザー  
> **I want to** マスコットをクリックしたり頭を撫でたりしたときに可愛いリアクションが返り、時折ふとした呟きや対話を楽しみたい  
> **So that** 単なる静止フィギュアではなく、生きているような愛着を感じられる。

## 6. 前提条件と制約事項

1. **Unityのライセンス & インストール**:
   - アバターの変換処理（`.dma` 生成）時のみ、アバターがセットアップされたUnityエディタがインストールされている必要がある。一度生成された `.dma` ファイルは、Unityが存在しない環境でもランタイム単体で動作可能。
2. **Windows DWM コンポジション**:
   - ウィンドウ透過処理はWindows DWMのハードウェアアクセラレーション機能に依存するため、Windowsリモートデスクトップなどの一部仮想環境では透過が黒背景になる場合がある。
3. **VRCSDKのバージョン互換性**:
   - 当面は VRCSDK3 (VRC PhysBone) をターゲットとする（旧Dynamic Boneは非推奨とし、Unityエクスポート時にPhysBone自動変換を推奨）。
